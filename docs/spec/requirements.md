# 요구사항 요약

출처: 프로젝트 요구사항 정의 v1.0 (2026-09-02). 이 문서는 요구사항 번호와 문서 구성 조건의 정본이다. 구현 상태는 `README.md` 체크리스트가, 설계 근거는 `DESIGN.md`가 소유한다. 요구사항 정의가 바뀌면 이 문서를 갱신한다.

## 필수 요구사항

### R1. 실시간 공간 스캔
- R1-1 카메라 프리뷰에서 실시간 스캔, 결과가 화면에 반영
- R1-2 스캔 제어: 시작 / 일시정지 / 재개 / 초기화
- R1-3 스캔 상태 피드백 (누적 포인트 수, 트래킹 품질, 커버리지 등 방식 자유)
- R1-4 트래킹 실패 상황 처리 — 앱이 죽거나 침묵하지 않을 것

### R2. Top-Down 실시간 Minimap (핵심)
- R2-1 실시간 갱신 — 스캔 종료 후 일괄 생성은 미충족
- R2-2 Top-down 투영
- R2-3 현재 위치·방향 표시
- R2-4 화면 오버레이 배치 + 확대/축소 또는 전체화면 전환
- R2-5 좌표계 기준(북향 고정 / 진행 방향 고정 / 시작 방향 고정)과 이유를 설계 문서에 명시
- 선택: 팬/줌/회전, auto-fit, 이동 궤적, 거리·면적 측정

### R3. 실시간 성능
- R3-1 스캔 중 UI 30fps 이상
- R3-2 3분 이상 연속 스캔, 메모리 강제 종료 없음
- R3-3 직접 측정한 수치를 README 또는 DESIGN에 포함 (평균/최저 FPS, 피크 메모리, 프레임당 처리 포인트 수, 기기 모델, 측정 방법). 목표 미달보다 미측정이 문제

### R4. UI/UX
- R4-1 설명 없이 스캔 시작·미니맵 판독 가능
- R4-2 권한 요청, 미지원 기기, 트래킹 불량 안내
- R4-3 디자인보다 조작 흐름의 명료함

## 선택 요구사항

- 3D 재구성 뷰어 (스캔 후 point cloud / mesh 표시, 회전·줌)
- 스캔 결과 저장·내보내기 (.ply / .obj / .usdz)
- 미니맵 거리·면적 측정
- 근거 있는 성능 최적화 (적용 전후 수치 비교 필수)
- 드리프트·정합 보정 시도
- 테스트 코드 (좌표 변환·격자 누적 단위 테스트)

미완성 부가기능은 포함하지 않는다. 필수 완성 후에만 착수.

## 문서 구성

- `README.md`: 실행 방법(클론→빌드→실기기), 테스트 기기 모델·iOS 버전, 오픈소스 출처·라이선스, 구현/미구현 체크리스트, 성능 측정 결과(R3), 알려진 버그·제약
- `DESIGN.md`: 전체 아키텍처, 실시간 파이프라인 전 과정, 미니맵 알고리즘(좌표 변환·바닥/천장·누적 자료구조·격자 해상도 근거), 스레딩·동시성, 성능 판단·측정 근거, 시간이 더 있었다면 개선할 지점
- `LLM_REPORT.md`: 도구·사용 방식·에이전트 컨텍스트 내용과 의도, 파일 단위 역할 구분 표, LLM 기각·수정 사례 1건 이상, 핵심 프롬프트 2~3개
- 데모 영상: 3분 이내 실기기 녹화. 스캔 시작 → 이동하며 미니맵 채워짐 → 종료 → (있다면) 3D 뷰. 미니맵과 실제 공간 대응이 보이게

## 필수 조건

- 저장소와 `README.md`만으로 빌드·실행 가능
- 미니맵은 실시간 갱신 (사후 일괄 생성 불가)
- LLM 활용 기록은 형식적 서술이 아닌 구체적 사례 포함
- 오픈소스 출처·라이선스 표기
- 의미 단위 커밋 (1~2개로 뭉치지 않음)

허용(설명이 있으면): 일부 미완성, 오픈소스 의존, LLM 비중 높음, 상용 앱 대비 품질, 디자인 완성도.

## 참고 영상 관찰 포인트

참고 영상(저장소에 포함하지 않음): 카메라 위 초록 mesh 와이어프레임, 좌하단 미니맵에 텍스처 top-down과 파란 위치 마커·시야 표시, 스캔 종료 후 2D/3D 결과 뷰와 측정 기능. 이 구현과의 차이는 `DESIGN.md` 11절.
