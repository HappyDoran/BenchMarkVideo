# 명세 대비 갭 분석과 보완 백로그

요구사항 명세 v1.0(`docs/spec/requirements.md`)과 현재 코드·문서를 대조한 결과. 요구사항 상태의 정본은 `README.md` 체크리스트고, 이 문서는 **"무엇이 비어 있고 어떤 순서로 채울 것인가"** 만 소유한다. 항목을 끝내면 체크하고 `README.md` 상태를 갱신한 뒤 `last_verified`를 맞춘다. 전부 끝나면 이 문서는 삭제 후보다.

점검 방법: 소스 10개 파일 전부 읽고 명세 4·5·6·8·9장과 대조. 코드에 있으면 "구현", 실기기 증거가 없으면 "미검증"으로 판정 (`AGENTS.md` 절대 금지 1항).

## 1. 판정 요약

필수 기능(R1~R4) 코드는 전 항목 구현돼 있다. 비어 있는 것은 **실기기 증거, 성능 수치, 데모 영상, LLM 리포트 필수 항목**이다. 남은 시간은 코드보다 측정·영상·리포트에 쓴다.

## 4. 가산점은 아니지만 품질 약점

- **바닥·천장 구분의 시작 높이 가정.** `OccupancyGrid.wallBand`가 스캔 시작 시 기기 높이(바닥 위 1.2~1.5m)에 의존한다. `ARPlaneAnchor` 수평면의 최저 y를 밴드 기준으로 쓰면 가정이 사라지고, 명세 7-2 "정답 없는 문제"에 대한 판단 근거가 된다. 실기기에서 앉아서 시작해 보고 실제로 깨지면 우선순위를 올린다 (`DESIGN.md` 6절 되돌리기 1순위).
- **커버리지 표기.** 상태 표시의 `cells` 수에 셀 면적(0.0025m²)을 곱해 m²로 보이면 R1-3 피드백이 한 줄 변경으로 읽기 쉬워진다.
