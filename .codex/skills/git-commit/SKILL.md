# 커밋 규칙

커밋은 의미 단위다. 제목은 무엇을, 본문은 왜와 어떻게 검증했는지를 적는다. 다음 세션은 현재 규칙을 문서에서, 과거 결정 이유를 커밋 본문에서 찾는다.

## 절차

1. `git status`와 diff를 보고 요청한 작업에 속한 파일만 stage한다. 관련 없는 변경은 남긴다.
2. `README.md` 검증 절의 명령(컴파일, `scripts/check-structure.sh`)을 실행한다. 실행하지 못한 검증은 본문에 "미검증"으로 적는다.
3. 제목과 본문을 분리해 커밋한다: `git commit -m "<제목>" -m "<본문>"`.
4. `git show -s --format='%s%n%b' HEAD`로 본문이 비어 있지 않은지 확인한다.
5. push는 사용자가 요청했을 때만 한다.

## 제목

```
<type>: <요약> [<주체>]
```

- `type`: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`.
- `주체`: `[llm]` LLM 생성, `[human]` 사람 작성, `[llm+human]` LLM 초안 + 사람 수정·결정. `LLM_REPORT.md` 역할 구분의 근거가 되므로 빠뜨리지 않는다.
- 한국어, 72자 내외. 예: `refactor: MVVM 계층 폴더링 — View→ViewModel→Model 단방향 [llm+human]`.

## 본문 (필수)

- 왜 바꿨는지. 구조적 결정이면 검토한 대안과 기각 이유를 한 줄씩.
- 중요한 구현 내용. 파라미터 값이 바뀌면 이전 값 → 새 값.
- 검증: 실행한 명령과 결과, 실기기 결과(`기기 × 시나리오 × 결과`), 실행하지 못한 검증.
- 함께 갱신한 소유 문서.

## 금지

- `Co-Authored-By`, `Claude-Session` 등 AI 트레일러를 넣지 않는다. 작성 주체는 제목 태그로만 표기한다.
- 본문 없는 커밋. 제목을 반복하는 본문.
- 여러 의미 단위를 한 커밋에 묶기 (예: 파이프라인 파라미터 변경 + 문서 체계 변경).
